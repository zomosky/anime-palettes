# 配色增补 · 标志物开关 · 自助加角色 —— 设计文档

日期：2026-08-06

三件事，互相独立，可以分别落地：

1. **增补 22 套配色**（36 → 58），堵上量出来的色相/彩度/明度空白，并把游戏与动漫的比例拉到 30 : 28
2. **色卡库 HTML 加标志物开关**，默认关闭
3. **`src/propose.py` + skill 文档**，让别人能自助加喜欢的角色，一次给 5 个调色方案挑

---

## 1. 现状审阅

### 1.1 family 计数会骗人

现有 36 套的 family 分布是 红4 橙4 黄3 绿4 青3 蓝7 紫3 粉3 中性3 撞色2。看上去只是蓝偏多、撞色偏少，
但把 36 个签名色投到 CIELAB 的色相角上排序后，真正的问题是四个连续空洞：

| 空洞 | 色相角跨度 | 缺的是什么 |
| --- | --- | --- |
| h 188 → 239 | **51°** | 湖蓝 / 孔雀 / 蔚蓝。miku 的青碧之后直接跳到 rei 的粉蓝 |
| h 88 → 128 | 40° | 黄绿 / 青柠 / 橄榄，一套都没有 |
| h 311 → 350 | 39° | 品红 / 洋红 / 紫罗兰 |
| h 145 → 171 | 26° | 正翡翠。附近只有 zoro / tanjiro 两套低彩度的墨绿 |

### 1.2 比色相洞更要命的两处

**彩度**：h 145°–305° 这半圈（绿-青-蓝-紫）**没有一个 C\* ≥ 55 的签名色**，最高只有 gojo 的 40。
画多系列图时这半圈拿不出鲜明主色。

**明度**：L\* < 35 的暗色签名只有 4 套（cloud 29.8 / taki 29.9 / 2b 20.0 / noface 20.2），
且**全部挤在 h 276–291 的蓝紫带**。红、橙、绿、青一个暗色签名都没有。

### 1.3 归类错误

`howl-iridescent` 的签名色是 `#C4548C`（h=350，粉红），却归在 `紫` family，检索时会误导。
本次一并修正为 `粉`。

### 1.4 IP 与题材比例

36 套 = 游戏 15（42%）+ 动漫 21（58%），共 19 个 IP，其中原神一家占 6 套（16.7%）。

**上表的 h / C / L 已经是 `tune()` 实测后的落点**，不是原始取色。原因见下。

#### tune 的可用窗口，以及它对极值的处理

`tune.py` 把 6 主色约束在 **L\* ∈ [30, 78]**（`MONO` 集合放宽到 [20, 86]），
外加 `_edge_penalty` 惩罚「对白对比度 < 2 或 > 14」。实测：

- `#1A1A1A`（L=9.3）→ `#404944`（L=30.1），**且色相漂到绿灰** —— 近中性色没有可锁的色相
- `#FFE600`（L=90.7, C=90）→ `#938400`（L=54.8）—— 荧光黄被腰斩

这不是缺陷：**6 主色是要画进图里的数据系列色，[30, 78] 就是可用窗口**。
现有 36 套本来就这样（`pikachu-lemon` 的 `#2B2B2B` 在库里是 `#444845`）。
真正的极暗 / 极亮由 `derive.py` 生成的 `ink` / `bg` / `bg2` / `dark[]` / `light[]` 承载。

所以「L9 最暗 / L89 最亮 / C102」这类断言**在 6 主色这一层拿不到**，本文档不再作此声明。
取色时直接在窗口内选，让 tune 少动，保真度更高。

### 2.3 结果

- 58 套 = **游戏 30 / 动漫 28**
- IP 数 19 → **33**，原神占比 16.7% → 10.3%
- **最大色相空洞 51° → 19°**（实测）
- **新增 22 套的色盲评级：A 级 12 / B 级 10，零个 C**；全库 58 套变成 A33 / B22 / C3
- **`dusk-inkvermilion`（h=20.3, L=32.9）成为全库唯一的暖调暗色签名**，填上 1.2 描述的空白
- `make tune` 约 40s → 约 65s，`src/library.json` 约 596K → 约 960K

family 分布（含 1.3 的 howl 归类修正 紫 → 粉）：

| | 红 | 橙 | 黄 | 绿 | 青 | 蓝 | 紫 | 粉 | 中性 | 撞色 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 现在 | 4 | 4 | 3 | 4 | 3 | 7 | 2 | 4 | 3 | 2 |
| 之后 | 5 | 4 | 5 | 6 | 7 | 9 | 5 | 5 | 7 | 5 |

**每个 family 都 ≥ 4**，最少的橙是 4 套。这是 2.4 那条「不按配额分配」原则下自然达成的结果 ——
先按色相 / 彩度 / 明度的空白选角色，family 均衡是副产品，不是目标。

### 2.4 明确不做的事

**不为凑数硬拉饱和度。** 增补完成后，h **145°–290°** 这一段的签名色彩度上限是
`minori-emerald` 的 45.5（增补前是 `gojo-sky` 的 40.3）—— 仍然没有 C\* ≥ 55。
把米哈游 / 明日方舟 / 鸣潮 / FGO / 绝区零全扫过一遍都没有：角色设计本来就极少用高彩青蓝（太刺眼），
这是色彩生理决定的，不是选角问题。

能拿到 C\* ≥ 55 的只有该段两端：`ichika-leoneed`（h=298, C=81）、`amiya-originium`（h=302, C=65），
以及原有的 `raiden-electro`（h=305, C=61）。中段靠 `derive` 的深浅变体补偿，不改角色本色去凑指标。

**family 不按配额平均分配。** 完成后黄仍是 3 套，但 h 78–88 那一带实际挤了
zhongli / nausicaa / zenitsu / pikachu / zelda 五个签名色 —— 黄不缺色，只是"黄"这个中文标签的
色相跨度天生比"蓝""绿"窄。覆盖度以色相 / 彩度 / 明度的分布为准，family 只是检索标签。

## 3. 标志物开关

### 3.1 画什么

**画角色相关的通用物件，用通用画法。** 祢豆子 = 竹筒，善逸 = 闪电，龙猫 = 叶伞，初音 = 葱，
马力欧 = 蘑菇，2B = 眼罩，无脸男 = 面具，褪色者 = 残剑，猫咪老师 = 铃铛，Inkling = 墨滴。

**判据（写进 `marks.py` 顶部注释）**：不画人物形象，也不复制作品的 logo、纹章、族徽、特定图案设计
—— 那些和角色形象一样受版权保护。艾伦画一对普通翅膀轮廓，不画"自由之翼"徽章。

这条判据的存在理由：本仓库 MIT 协议、已发布到 GitHub Pages 公开访问，
可辨识的角色剪影是版权角色的衍生形象，不能进仓库。

### 3.2 数据流

新增手写数据源 `src/marks.py`，与 `data.py` 并列：

```
src/data.py  ──→ tune ──→ derive ──→ library.json ──→ gen_html.py ──→ dist/*.html
src/marks.py ──────────────────────────────────────────↗
```

`MARKS = {slug: (viewBox, path_d)}`，58 条。

**关键取舍：`marks.py` 只喂 `gen_html.py`，不进 `derive.py`。**
标志物不是色彩科学数据。让它进 `library.json` 会污染纯色彩数据，也会破坏
`dist/anime_palettes.json` 与 `src/library.json` 内容完全相同这条不变量。

### 3.3 交互

- 开关放进现有那排 `.seg`：`<div class="seg" id="mark"><button id="mkbtn">标志物</button></div>`
- **默认关闭**（无 `.on` 类）。不持久化 —— 与现有的深色界面开关行为一致，刷新即复位
- 关闭时**完全不插入 DOM**，零渲染开销
- 开启时在卡片头 `.chead` 右侧渲染 44×44 SVG，`fill` 取该套的**签名色**，标志物本身就是一块色样
- **色盲模拟开启时标志物一起走 `sim()`**，与色块行为一致，不搞特例

### 3.4 代价

58 个 path 约 70K，`dist/anime-palettes.html` 从 100K 涨到约 175K（含 22 套新配色的数据）。
仍是单文件自包含，Pages 直接发布，不引入外部资源。

## 4. 自助加角色：`src/propose.py`

### 4.1 用法

```bash
python src/propose.py --slug my-char --zh 角色名 --en Name \
    --tone-zh 霜蓝 --tone-en Frost --family 蓝 --source 出处 \
    --colors "#4FA8DE,#9CD2F0,#2A6BA5,#1F2430,#B9C4D0,#EAF2F8"
```

### 4.2 五个调色方案

差别在 `tune` 的目标函数取向：

| 方案 | 取向 | 实现 |
| --- | --- | --- |
| **A 忠于原作** | 色几乎不动 | 偏离惩罚 0.55 → 1.6，色相锁死 ±2° |
| **B 区分度优先** | 拉最大两两 ΔE₀₀ | 惩罚降到 0.25，L\* 放宽到 [26, 82] |
| **C 色盲友好** | 冲 grade A | `weight_cvd` 0.65 → 1.6 |
| **D 灰度打印** | L\* 均匀铺开 | 目标函数加 L\* 间距项 |
| **E 柔和低饱和** | 大面积填充 / 背景 | C\* 上限压到 0.85×，L\* 抬到 [42, 84] |

### 4.3 每个方案输出可比的体检数据

6 色 hex、minΔE₀₀、色盲 ΔE、grade、安全子集 n/6、灰度最小 ΔL\*，
以及**相对原色的平均偏移 ΔE₀₀** —— 把"忠于原作"量化，不靠感觉。

终端用 ANSI 真彩打三行预览：正常 / 红色盲 / 灰度。零依赖。

`--html` 额外生成 `build/propose-<slug>.html`：5 个方案并排 + 每个的 4 条色标。
这个预览页**只依赖 `colorlib` 自渲染，不依赖 `library.json`**，全新 clone 上也能直接跑。

### 4.4 落地

`--apply B` 做三件事：

1. 追加记录到 `src/data.py` 对应 family 分组末尾
2. 把该 slug 的调优结果 **merge 进 `src/tuned.py`**（`tune()` 逐套独立，其余 slug 不受影响，
   单套约 1s，不用重跑 65s 全库）
3. 重算 `SOURCE` 指纹

然后提示用户跑 `make all && make skill`。

### 4.5 一条硬约束

改造 `tune.py` 时要把 `0.55`、`weight_cvd=0.65`、`LMIN` / `LMAX` 收进 profile 参数，
但**默认 profile 的数值必须与现状逐位一致** —— 否则现有 36 套的 `tuned.py` 会变，
CI 那道逐字节 diff 直接红。加一个回归测试专门钉住这点。

### 4.6 skill 侧

- 新增 `skills/anime-palettes/references/add-palette.md`：取色建议 / 5 个方案怎么选 / 常见坑
- `SKILL.md` 加一节「自己加一套配色」指过去
- `make skill` 重新打包；CI 的 skill 一致性检查（速查表无 diff + `.skill` 与目录逐文件一致）自动覆盖

## 5. 测试策略

现有 366 项测试多数按 slug 参数化，新增 22 套会自动纳入。额外要加的：

**配色增补**
- `test_family_is_valid` —— family 必须在 `FAMILY_ORDER` 里
- `test_slug_is_unique`
- 覆盖度回归：最大色相空洞 ≤ 25°；L\* < 35 的签名色不再全部落在单一色相带

**标志物**
- `test_every_slug_has_a_mark` —— `MARKS` 的键集合 == `PALETTES` 的 slug 集合
- `test_mark_path_is_wellformed` —— `d` 只含合法 SVG 路径命令字符；`viewBox` 是四段数字
- `test_html_has_marks_off_by_default` —— 生成的 HTML 里 `#mkbtn` 不带 `on` 类

**propose.py**
- `test_default_profile_reproduces_tuned` —— 默认 profile 对现有 36 套的输出与 `tuned.py` 逐色一致（第 4.5 条的钉子）
- `test_all_profiles_produce_valid_hexes` —— 5 个 profile 都给出 6 个合法 hex
- `test_apply_writes_valid_python` —— `--apply` 产生的 `data.py` / `tuned.py` 可被 import
- `test_fingerprint_recomputed` —— `--apply` 后 `SOURCE` 与 `source_fingerprint()` 对得上

## 6. 风险与已知限制

**荧光色调优后会回落。** 已实测：Inkling 的荧青柠 `#5FD424`、猫又的 `#E8D42E` 都被压暗压灰。
签名色本身保住了（Inkling C=77、猫又 C=78、Joker C=93），但副色损失明显。2.2 的表已按实测值填写。

**h 145°–290° 的彩度上限 45.5。** 见 2.4，不硬凑。

**取色必须落在 [30, 78] 窗口内。** 否则 tune 会把它拽回来，还可能把近中性色的色相甩到别处
（`#1A1A1A` → `#404944` 绿灰）。这条要写进 `references/add-palette.md`，是别人自助加配色时最容易踩的坑。

**HTML 体积翻 1.75 倍。** 100K → 约 175K。仍在单文件自包含的合理范围，但如果后续再翻倍，
需要重新考虑是否把标志物拆成外部资源（那会牺牲单文件属性，需另行决策）。

**`--apply` 会改写手写源文件 `data.py`。** 追加式写入，但仍建议用户在 git 干净时使用，
出问题可以 `git checkout`。文档里写明。
