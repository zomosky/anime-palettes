# 自己加一套配色

库里 58 套没有你想要的角色？三步加进去。全程零依赖，只要 Python 3.8+ 和这个仓库。

```bash
git clone https://github.com/zomosky/anime-palettes.git && cd anime-palettes
```

---

## 1. 取 6 个色

从角色立绘里吸 6 个色：**主色 + 一个浅一档 + 一个深一档 + 2-3 个点缀色 + 一个背景/中性色**。

这 6 个色是要当**数据系列**画进图里的 —— 折线、柱子、散点。不是拿来铺满整张画布的。
真正的极暗极亮由 `derive.py` 自动派生的 `ink` / `bg` / `dark[]` / `light[]` 承载，不用你操心。

> 下面会用到三个 CIELAB 的量：**`L*`** 是明度，0 全黑、100 全白；**`C*`** 是彩度，
> 越大越鲜艳、0 就是灰；**`h`** 是色相角，0–360°（约莫 0° 品红、40° 红、90° 黄、
> 140° 绿、200° 青、270° 蓝）。调优器的规矩是**锁 `h`、只动 `L*` 和 `C*`** ——
> 角色的辨识度在色相上，所以色相不许乱跑。

### 坑一：色值必须落在 `L* ∈ [30, 78]`

调优器把 6 主色约束在这个明度窗口里（各方案略有出入：B 放宽到 `[26, 82]`、D 是 `[28, 80]`、
E 抬到 `[42, 84]`；加 `--mono` 跑单色相配色则一律放宽到 `[20, 86]`）。
超出窗口的色会被**硬拽**进窗口里 —— 不是提示一下就算了，是真的改掉，
而且不止拽到边界：一旦进了窗口它就跟别的色一起参与优化，最后可能停在窗口中间。

`propose.py` 会在跑之前把越界的色打到 stderr 上提醒你，但拽还是照拽。实测两例，
取色集 `#1A1A1A,#FFE600,#FFD166,#EF476F,#118AB2,#073B4C`：

| 原始色 | L\* | A 忠于原作 | E 柔和低饱和 |
| --- | --- | --- | --- |
| `#1A1A1A` 纯黑 | 9 | `#464746`（L\*30） | `#626D66`（L\*45，**发绿的灰**） |
| `#FFE600` 荧光黄 | 91 | `#9A8A00`（L\*57） | `#A49400`（L\*61） |

荧光黄被腰斩是意料之中的。**纯黑变绿灰不是** —— 值得单独说一句：

> sRGB 里的纯灰（`#1A1A1A` `#808080` `#FFFFFF` …）转到 CIELAB 之后 a\*/b\* 只剩
> 1e-5 量级的浮点残差，彩度实际是 0；可色相角是拿这点残差做 `atan2` 算出来的，
> 于是纯灰全都得到同一个 **h ≈ 158°**（青绿方向）—— 是噪声，不是真色相。
> 调优器的规矩是「锁色相、只动 L\*/C\*」，它分不出真假，照样锁住这个 158°，
> 再在允许范围内把彩度抬上去换区分度（中性色的彩度上限有个 6.0 的地板），
> 结果就是一个肉眼可见的绿灰。

所以**别放纯黑纯白**。要中性色就放一个本来就有轻微倾向的灰（比如 `#5E6B7A` 蓝灰、
`#6E7480` 冷灰），色相是你定的，调优器就只会顺着你定的方向走。

### 坑二：色相**落在哪**，比色相**差多少**要紧得多

红/绿色盲的模拟本质上是把一条特定的轴压掉。同样大的色相差，跨在这条轴上就几乎全没了，
跨在别处就基本不损失 —— 差别能有一个数量级。

实测：两个色，同明度 `L*=55`、同彩度 `C*=40`、**色相固定差 30°**，只挪它们在色相环上的位置。

| 两色的色相 | 两个色 | 正常 ΔE₀₀ | 色盲 ΔE₀₀ | 判断 |
| --- | --- | --- | --- | --- |
| 345° → 15°（玫红→绯红） | `#BB6997` `#C56773` | 11.7 | **16.4** | 几乎不损失 |
| 165° → 195°（翠绿→青） | `#2A9471` `#009392` | 12.4 | **15.6** | 几乎不损失 |
| 0° → 30°（粉红→砖红） | `#C36785` `#C46A63` | 12.5 | 12.3 | 尚可 |
| 120° → 150°（橄榄绿→草绿） | `#758C46` `#499260` | 11.5 | 5.9 | 已经危险 |
| 300° → 330°（蓝紫→紫红） | `#867BC0` `#AE6EA7` | 13.7 | 5.2 | 已经危险 |
| **60° → 90°（橙棕→橄榄黄）** | `#B47548` `#98823C` | 15.9 | **1.6** | **等于同一个色** |
| **255° → 285°（天蓝→蓝紫）** | `#038CC6` `#6A81C6` | 14.6 | **1.3** | **等于同一个色** |

正常视觉下这 7 组差不多一样好分（11.5–15.9），色盲下却从 16.4 一路塌到 1.3，差 12 倍。
**橙—黄区（h≈60–90°）和蓝—蓝紫区（h≈255–285°）是两个雷区**，
玫红/粉区（h≈345°）和翠绿区（h≈165°）反而最抗打。

色相差拉大也救不了 —— 把差距从 30° 拉到 100°（明度也差开，L\*47 配 L\*42），
正常 ΔE₀₀ 全都涨到 30 以上，色盲下照样有塌的：

| 两色的色相 | 两个色 | 正常 ΔE₀₀ | 色盲 ΔE₀₀ |
| --- | --- | --- | --- |
| 320° → 60°（紫→橙棕） | `#8E5E9B` `#8F552A` | 36.5 | 39.1 |
| 140° → 240°（绿→青蓝） | `#457C42` `#006C8C` | 35.7 | 36.1 |
| **40° → 140°（砖红→绿）** | `#A95946` `#386F37` | 45.5 | **5.1** |
| **220° → 320°（青→紫）** | `#007B8E` `#80518E` | 35.0 | **2.9** |

红配绿正是库里千寻·朱绿掉到 C 的原因：`#C6402E`（h38 L\*47）和 `#536950`（h140 L\*42）
在红色盲下 ΔE₀₀ 只有 8.9，差 0.1 就够 B 级。

还有一条：**低彩度没有余地，而高彩度也救不了雷区。** 同样是 h30 配 h60、同明度，
把彩度从 `C*=10` 一路开到 `C*=60`，正常 ΔE₀₀ 从 5.5 涨到 19.3（涨了 3.5 倍），
色盲 ΔE₀₀ 却只从 2.6 爬到 6.4 —— 全程不及格。
落在雷区的色相对，靠加饱和度是拉不回来的，得换色相或者把明度拉开。

**那「别放 3 个同色系的色」这种说法呢？** 方向对，但**别当成阈值记**。
跑了 60 组随机色相家族（家族色相随机、其余色在色相环上均匀铺开、明度彩度也随机，
只改「几个色留在同一色相带里」）：

| 同色相带的色数 | A | B | C |
| --- | --- | --- | --- |
| 2 个 | 61.7% | 35.0% | 3.3% |
| 3 个 | 51.7% | 46.7% | 1.7% |
| 4 个 | 48.3% | 40.0% | 11.7% |
| 5 个 | 26.7% | 46.7% | 26.7% |

趋势是有的（挤得越多越差），但**没有哪一个数字是分水岭**：光放 2 个同色系就已经有 3.3%
掉到 C，放到 4 个还有 48% 是 A。60 组里只有 9 组符合「2、3 个是 A，第 4 个掉档」，
评级随色数单调变差的也只有 38 组。**掉不掉档由这组色落在色相环的哪一段、彩度多高决定，
不由个数决定。**

所以别数色数 —— **跑一次 `propose.py` 看实测评级**，两秒钟的事。
真想要「深浅三档同色」的效果，用库里自带的 `dark[]` / `light[]` 变体，
不要占用 6 主色的名额。

## 2. 生成 5 个方案挑一个

```bash
python src/propose.py --slug my-char --zh 角色名 --en Name \
    --tone-zh 霜蓝 --tone-en "Frost Blue" --family 蓝 --source 出处 \
    --colors "#4FA8DE,#7BC6E8,#2A6BA5,#C86A7A,#D8B25C,#5E6B7A" --html
```

`--family` 只能取 `红 橙 黄 绿 青 蓝 紫 粉 中性 撞色` 之一。
终端会打出 5 个方案的色块（正常 / 红色盲 / 灰度三行）和一张体检表，
`--html` 再出一个带 4 条色标的对比页，落在 `src/build/propose-my-char.html`。

上面那条命令的真实输出：

```
    方案          minΔE  色盲ΔE 级  安全 灰度间隔   偏移
A   忠于原作       15.2    14.0  A   6/6      1.0    2.8
B   区分度优先     17.8    15.6  A   6/6      0.4    5.8
C   色盲友好       17.7    16.4  A   6/6      3.7    4.0
D   灰度打印       15.3    13.7  A   6/6      3.8    5.3
E   柔和低饱和     15.0    14.2  A   6/6      0.4    4.2
```

### 五个方案怎么选

五个方案的差别只在调优的**目标函数取向**，不在色相 —— 角色的辨识度色相始终锁着。

| 方案 | 内部改了什么 | 什么时候选它 |
| --- | --- | --- |
| **A 忠于原作** | 偏离惩罚 ×3、色相几乎焊死（±2°） | 角色配色本身就够分，只想要个规范化版本 |
| **B 区分度优先** | 偏离惩罚压到 0.25、明度窗口和彩度上限都放宽 | 要画 6 条线 / 6 组柱，色差最重要，能接受色值偏离原作 |
| **C 色盲友好** | 色盲项权重 ×2.5 | 投稿有无障碍要求，或者读者群里有色觉障碍 |
| **D 灰度打印** | 加一项明度间距奖励、色盲项权重降低 | 黑白期刊、复印件，靠深浅而不是色相区分 |
| **E 柔和低饱和** | 彩度上限压到 0.85 倍、明度下限抬到 42 | 大面积填充（地图、堆叠面积图）或者当背景，高饱和会刺眼 |

**按表挑，不要按名字挑。** 每个方案只是把某个旋钮拧大了，不保证它就赢下同名的那一列。
最好的反例：拿全库 58 套的原始取色各跑一遍 5 个方案，看谁的色盲 ΔE 最高 ——
**B「区分度优先」赢了 31 套，C「色盲友好」只赢了 23 套**（其余 A/D/E 合计 4 套）。
因为 B 把偏离惩罚压得很低、明度窗口也放宽了，往往顺手把色盲区分度一起拉了上去。
上面那张示例表里 C 确实赢了色盲这一列，但那只是这一套的结果，换一组取色就未必。

同一次统计里 B 倒是名副其实地拿下了 minΔE₀₀ 这一列：58 套里赢 38 套。
而 E「柔和低饱和」在示例表里一列都没赢 —— 它图的是低彩度本身，不是某个指标。

### 怎么读体检数据

- **minΔE₀₀** —— 正常视觉下 6 色两两最小色差。库里 58 套最低的是 10.7（无脸男·墨灰），
  中位数 19.0，最高 28.8（花里みのり·翡翠）。**低于 10 就该回第 1 步换色**
- **色盲ΔE** —— 红/绿色盲模拟下的最小两两色差，两种色盲取更差的那个
- **级** —— 由色盲 ΔE 直接判定：**≥ 13 是 A**（6 色全可分）、**≥ 9 是 B**（大部分可分）、
  否则 C（只能用安全子集）。全库现状 A 30 套 / B 23 套 / C 5 套
- **安全 n/6** —— 色盲下两两 ΔE₀₀ ≥ 12 的最大子集大小，就是 `ap.safe(slug)` 会返回的那几个
- **灰度间隔** —— 6 个色按明度排序后相邻的最小间隔。要黑白打印就挑这一列大的
- **偏移** —— 相对你原始取色的平均 ΔE₀₀，**越小越忠于原作**

## 3. 落地

```bash
python src/propose.py ...（跟上面完全一样的参数）--apply B
make all && make skill
```

`--apply` 会把记录追加进 `src/data.py`、把选中方案并进 `src/tuned.py` 并重算指纹。
因为调优是逐套独立的，加一个角色只要一两秒，**不用重跑 `make tune`**（那是全库重跑，几十秒）。

`make all` 重新生成全部交付物（Python 模块、HTML 色卡库、Excel、ase、gpl、PPT 主题色…），
`make skill` 更新 58 套速查表并重新打包 `.skill`。
**这两步都不能省** —— CI 会重跑生成链路逐字节比对产物，也会重新生成速查表 diff。

只有取色和 `propose.py` 是零依赖的，`make all` 要装东西：
`uv sync --extra build`（或 `pip install matplotlib numpy openpyxl`）+ `node`。
装不全就分步跑 `make derive py html` —— 这三步零依赖，Python 模块和 HTML 色卡库先出来，
xlsx / pptx / 文档配图那几步再补。

不满意就回滚，两个文件之外没别的手写改动：

```bash
git checkout src/data.py src/tuned.py
```

## 常见问题

**评级出来是 C 怎么办？** 说明 6 色在色盲下并团了。先试 C 方案；还是 C 的话，
回第 1 步看有没有色落进坑二那两个雷区（橙—黄 h≈60–90°、蓝—蓝紫 h≈255–285°），
或者有没有一对红配绿、蓝配紫而明度还撞在一起。挪色相比加饱和度管用。
库里的原则是**如实标注不粉饰**，C 级配色照样收录，只是用的时候要走 `ap.safe(slug)` 取子集。

**改了 `data.py` 里已有配色的色值怎么办？** 那必须跑 `make tune`（全库重跑，几十秒）。
漏了这步改动会完全失效 —— `derive.py` 读的是 `tuned.py`，`data.py` 里的 `colors` 只当元数据留档。
不过 `tuned.py` 里存了生成时 `data.py` 的指纹，对不上时 `derive.py` 会直接报错退出，
`test_tuned_is_in_sync_with_data` 也会红，跑不掉。

**角色名或出处里有引号怎么办？** 用中文引号「」或“”。`--apply` 遇到英文双引号会直接拒绝
并退出，因为那会把 `data.py` 写成语法错误 —— 它在动文件之前就拦下来，不会留半截写入。

**想加标志物图形？** 往 `src/marks.py` 加一条 `slug -> (viewBox, path_d)`，
`viewBox` 一律 `"0 0 24 24"`，单条 path，纯填充无描边，主体占 20×20 留 2 单位边距。
规矩是**只画角色相关的通用物件、用通用画法**（祢豆子 = 竹筒，初音 = 葱，2B = 眼罩），
不画人物形象，也不复制作品的 logo / 纹章 / 族徽 —— 那些和角色形象一样受版权保护。
路径必须按默认的 `fill-rule: nonzero` 画，文件头有说明，别去改。

**想让新配色也进在线色卡库？** `make all` 生成的 `dist/anime-palettes.html` 就是它，
本地直接打开即可；推上 main 之后 GitHub Pages 会自动发布。
